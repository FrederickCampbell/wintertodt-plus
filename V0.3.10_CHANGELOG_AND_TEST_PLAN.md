# Wintertodt+ v0.3.10

## Scope
Thread-safety + logging QoL hotfix. No planner strategy/mechanics changes.

## Fixed
- Config changes from the Swing sidebar no longer call client-only APIs from the AWT thread.
- Client-sensitive config refresh work is marshalled through RuneLite `ClientThread.invokeLater`.
- Fixes `AssertionError: must be called on client thread` from `WintertodtState.inWintertodt()` when editing settings.

## Logging
- Normal `run` uses `--developer-mode` only.
- New `runDebug` uses `--developer-mode --debug`.
- Detailed `[WT+AUDIT]` tracing has a separate `Planner trace` toggle and defaults OFF.
- Audit formatting/state tracking is inactive unless both Planner trace is enabled and RuneLite debug logging is active.
- Routine Wintertodt+ startup/LAF diagnostics are debug-level rather than INFO.

## Test
1. Start with normal RUN.bat.
2. Change steppers, checkboxes, Goal, colors, and presets in the sidebar. No client-thread assertion should occur.
3. Play normally: Session Trace should say Off and no `[WT+AUDIT]` lines should be produced.
4. Diagnostic test only: launch RUN_DEBUG.bat, enable Debug / Session Trace / Planner trace, play a round, then disable it.
5. Verify Max FM XP and Max Points behavior is unchanged from v0.3.9.
